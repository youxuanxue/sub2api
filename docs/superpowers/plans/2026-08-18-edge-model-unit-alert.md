# Edge Model Unit Alert Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace account-inventory Edge paging with high-precision alerts driven by complete, per-model terminal empty-pool 429 outcomes.

**Architecture:** A standalone Go terminal recorder attaches to explicitly classified gateway routes, accumulates bounded request outcomes without synchronous I/O, and flushes minute facts plus completeness heartbeats to PostgreSQL. The Edge probe returns complete five-minute terminal buckets; a pure Python evaluator groups known models by a generated Go-owned family artifact, creates dynamic exact-model units only after real empty-pool 429 traffic, and advances durable alert state only after acknowledged delivery.

**Tech Stack:** Go 1.24, Gin, `database/sql`, PostgreSQL, Python 3 standard library, Bash, GitHub Actions, existing Feishu delivery helper.

## Global Constraints

- `ops_error_logs`, its taxonomy, queue, DLQ/fallback, insert health, and watermarks are diagnostic only and never gate this alert.
- The request hot path performs no synchronous database or network I/O.
- Known models aggregate by family; an unclassified model becomes a dynamic exact-model candidate only after `final_empty_pool_429 > 0` in the evaluated trigger window.
- Orange: two consecutive complete five-minute buckets each have at least 10 empty-pool 429s and at least 20% empty-pool ratio.
- Red: one complete bucket has at least 50 empty-pool 429s, or two consecutive complete buckets each have at least 10 and at least 80% ratio.
- Recovery requires either three consecutive complete nonzero buckets each below 5 and 10%, or three consecutive complete `0/0` buckets reported as `traffic_stopped`.
- Inactive `0/0`, zero-account, thin, and single-account posture never creates alert state or a Feishu notification.
- Every gateway route registered by `gateway.go` or its video registration helper has exactly one terminal policy at its registration site.
- Existing prod user-visible-failure alerts, host-unreachable alerts, and manual account posture remain independent.

- [ ] **Step 4: Implement the fixed-capacity nonblocking queue and single-owner flusher**

```go
type TerminalOutcomeKind string
const (
    TerminalOutcomeSuccess TerminalOutcomeKind = "success"
    TerminalOutcomeFinalEmptyPool429 TerminalOutcomeKind = "final_empty_pool_429"
    TerminalOutcomeOtherError TerminalOutcomeKind = "other_error"
)
type TerminalOutcomeEvent struct { At time.Time; GroupID int64; RequestedModel string; Kind TerminalOutcomeKind }
```

The recorder increments per-minute atomic `seen/drop` slots before a nonblocking channel send. Its worker batches accepted events, retries failed transactional flushes without discarding deltas, writes zero heartbeats, and closes a minute only after the one-minute lateness allowance with `seen == persisted`, no drop, no flush failure, and one epoch.
