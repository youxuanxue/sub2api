## 目标与当前结论

处理 Claude Code auto-mode 安全分类请求在 Kiro 上的尺寸不兼容，同时尽量保留其授权判定所需的上下文。
请求变小或不再报 413，不能单独作为修复成功的标准。

沿用此前上游实测支持的本地容量保护，不重复探测容量边界，也不放宽阈值。
网关承担兼容责任，但采用“结构化减肥”而不是按字符猜测内容：保留用户原话和最新动作，
先去掉旧的、可重新执行而不携带授权的工具过程记录；无法安全判断时继续 413。

本文件是修订后的方案建议，保留 pending 状态，不把会话中的方向确认扩大为生产上线授权。

## 已有证据与适用范围

| 证据 | 可以得出的结论 | 不能据此推断的内容 |
| --- | --- | --- |
| 此前已做上游超限实测，用户在本次复审再次确认 | 上游容量限制真实存在；保留现有 `maxPayloadBytes` 保护，不重复容量实验 | 所有模型、端点和未来版本都具有完全相同的精确字节边界 |
| 本批 11 次错误在本地转换及尺寸校验后返回 413，没有上游调用 | 失败由本地保护触发；与此前上游实测并不矛盾 | 这 11 次已逐条发送上游，或者上游一定能接受它们 |
| UA 为 `claude-cli/2.1.301 (external, cli)`；QA 前缀含安全分类 system、`<transcript>` 和小输出预算 | 与 auto-mode 分类请求高度吻合 | 单凭 UA 证明实际客户端二进制身份 |
| 官方 2.1.301 包静态检查发现 `jGo` 有意拼装 transcript，并在客户端调用路径使用 `querySource: "auto_mode"` | 把历史包装成 user 文本是该分类器的有意行为，不应直接归为聊天角色丢失 bug | `querySource` 已在生产入站正文中观测到 |
| QA 仅保存 256 KiB 前缀，末尾截在文本块内部 | 可分析已保存部分和超限机制 | 完整重放 11 次请求、还原最终动作，或用前缀 hash 证明请求完全相同 |
| 前缀加合成尾部的离线转换实验中，chunking 开关不缩短普通 transcript 文本 | `kiro_file_tool_chunking` 不能解决这种已有输入；它指导未来文件工具输出 | 合成尾部就是原用户内容，或本地校验通过等于上游成功 |

本地预算的实现 owner 为 [translator.go](../backend/internal/integration/kiro/translator.go) 的
`maxPayloadBytes` 和现有转换后大小校验；本方案不另设一套 transcript 字节预算。
此前上游实测与本次离线前缀实验是不同证据，不混写为同一次完整线上重放。

## 为什么撤回通用裁剪策略

Claude Code 2.1.301 的分类器提示明确使用 assistant 提案解释用户简短的“同意”，
使用中间第三方消息判断该确认是否存在歧义，并读取工具结果、动作和附属上下文。
因此，assistant 文本和工具输出不能仅凭角色名就全部删除；只保留最新用户意图和最新动作也会丢失更早的范围限制、禁止或撤回。
单条消息只保留头尾可能删除中间的否定句、作用对象或命令参数。
添加“已截断”标记只能告知信息缺失，不能恢复这些信息或保证分类器保守拒绝。

网关要做的是一条有明确优先级的结构化减肥路径：

1. 先测量转换后的真实大小，并保留原始请求诊断。
2. 只在已识别为 Claude Code auto-mode、且 transcript 是逐行结构化记录时进入此路径；普通 user 文本不进入。
3. `<transcript>`、结尾标记和最新 action 完整保留；不在 JSON 记录中间按字节切断。
4. 所有真实 `user` 记录原文保留，包括早期禁止、范围限制、撤回和第三方消息；用户原文是授权证据，不能为了凑大小删除。
5. 最新工具调用及其参数完整保留。最新 action 前紧邻的 meta/outcome 记录一并保留，避免丢失执行状态。
6. 超限时从最旧到最新依次删除**完整的旧工具过程记录**（如已经结束的 Bash/Read/Write/Edit 调用及其结果），每删一条都重新测量；删除记录之间插入固定的“旧工具过程已省略”标记。
   这一步不删除用户话、不改写最新 action，也不把工具内容误当用户授权。
7. 如果仍然超限，再删除最旧的非授权元数据记录；不得删除用户记录、最新 action、授权链或安全系统提示。
8. 仍超限就保持现有 413，不调用上游。不能用 assistant 文本摘要、单条 head/tail 裁剪或模型自动总结来强行塞入。

这条路径的目标是把这批请求中大量旧 Bash/工具过程从“当前 user 正文”移到可丢弃的历史噪声位。
它不能保证所有请求都成功，但每一次删除都有明确的语义优先级，并且失败时安全关闭。

社区证据的正确用法：

- [iTerm2 AutoModeClassifier](https://github.com/gnachman/iTerm2/blob/ad80b196b4447bd6a99b572de7009dc1ad59db8d/sources/AITerm/AutoModeClassifier.swift)
  对自己的结构化历史做容量限制，待审动作另行传入；其角色类型和安全提示与 Claude Code 不同。
  它证明客户端可以设计有界分类输入，不能证明代理可以直接照搬其裁剪策略。
- [claude-auto-permission](https://github.com/kevinhwang/claude-auto-permission/blob/d015838/docs/llm-classifier-design.md)
  使用自己的输入投影和判定规则；删除 assistant 文本的做法不能脱离那套分类器使用。
- 已检查的 KiroProxy、kiro-lb 实现主要裁剪外层历史；未找到可直接复用、已验证适配该版本 Claude Code 安全 transcript 的裁剪实现。
- [kiro-lb 的容量实验](https://github.com/minpeter/kiro-lb/pull/26)
  使用不同模型和账号，不能推翻本项目此前上游实测，也不能作为直接放宽本地保护的依据。

## 当前交付范围

完成已获授权的诊断改动，并为上述结构化减肥器保留一个独立、可回滚的原型入口；不新增全局开关：

- Kiro 本地超限记录转换器输入大小/hash、现有裁剪前后序列化大小以及 system、history、current text、工具等组成。
  转换器输入可能已经过 schema 等处理，不标为原始入站 wire。
- QA 区分实际读取的 wire 字节/hash、读取是否完整，以及保存/脱敏后正文的字节/hash。
  只有读到 EOF 且无读取错误时才声明完整 wire hash；不改变旧 `request_sha256` 的含义。
- 新增诊断只包含大小、计数、完整性和 hash，不附加用户正文，不扩大 QA 正文保存上限。
- 普通请求继续走现有本地 413 路径；只有结构识别成功的 auto-mode transcript 才尝试按上述顺序减肥。
- 每次减肥都在最终转换后的 Kiro payload 上重新测量；不因尺寸错误跨账号重试，不放宽 Kiro 限制。
- 减肥结果写入内部诊断（检测、删除类别/条数、前后大小、hash），不记录正文。

本方案不修改生产服务、账号、路由、计费、超时或权限模式，不伪造分类器允许结果。

## 用户可见的处理路径

| 路径 | 价值与代价 | 当前状态 |
| --- | --- | --- |
| 在客户端使用普通权限确认模式 | 避开这类 auto-mode 辅助分类请求；增加用户确认次数 | 待在受控客户端验证；不代表所有大请求都不会超限，不自动代用户切换 |
| 显式选择已验证能承接完整输入的供应源 | 保留自动模式及完整分类输入；供应源、费用和数据去向可能变化 | 当前未选定供应源；不自动跨平台路由 |
| 客户端压缩或修复其分类器输入生成 | 客户端掌握真实角色和协议，更适合决定输入组织方式 | 未验证具体版本、配置或修复；不能承诺升级或 `/compact` 一定有效 |
| 网关按结构删除旧工具过程记录 | 有机会缩小正文；会减少历史操作上下文，但保留用户授权和最新动作 | 本方案优先验证 |
| 网关按标签删除、摘要或头尾截断 transcript | 有机会缩小正文，但会改变安全审查材料 | 明确不实施 |

诊断交付与用户体验修复分别验收。普通权限确认会减少自动化，不能悄悄作为默认产品修复；
保留自动模式的长期处理仍需客户端兼容修复或能承接完整输入的供应源。

## 验证与完成标准

诊断改动按既有测试验证：小请求转换结果不变；超限仍返回 413 且不调用上游；
现有裁剪前后各项字节组成可核对；内部错误细节经过 middleware 保留且不泄露到公开响应。
QA 覆盖相同前缀不同尾部、恰好达到捕获上限、未完整读取、读取错误和 gzip wire/解码口径。
复用已有 Kiro、QA、service 和 handler 聚焦测试与 preflight；本文修改本身不新增测试代码。

## 原型验收门槛

不重复容量边界调研；只验证结构识别、删除顺序和安全保留项：

1. 明确支持的实际格式、版本、角色来源、转义及边界规则；伪造标签、嵌套标记或无法判断的输入不得改写。
   UA、`<transcript>`、小输出预算等特征只能用于识别候选，不能独立授权删除正文。
2. 对逐行 JSON 记录做完整解析；任何解析错误、重复结束标记、缺少最新 action 或记录角色不明，都直接保持原文并 413。
3. 测试用户原文完整保留，最新 action 和相邻 meta/outcome 完整保留，旧工具记录只按从旧到新的顺序整条删除。
4. 用完整受控样本覆盖允许与拒绝、先禁止后简短确认、撤回、assistant 提案后的确认、第三方插入、
   中间否定和伪造角色等场景；先验证未修改输入的预期判定，再对比减肥后的判定。
5. 分别报告尺寸达标、上游接受和安全判定结果。通过有限样本不宣称普遍语义等价；
   缺少完整原请求时，不宣称已逐条修复这批事件。

当前候选是“旧工具过程记录整条删除”；assistant 摘要、用户消息删除、单条 head/tail 裁剪和模型总结均淘汰。
满足以上门槛前不进入生产；诊断通过也不代表网关减肥器可以上线。
