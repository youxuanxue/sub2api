## 七、服务质量（SLA）参数

| 参数项 | 建议控标值 | 强度 |
|---|---|---|
| 可用性口径（强制写明） | `SLA = (请求总数 − 服务方故障数) / 请求总数`，其中服务方故障 = HTTP ≥400 且 `error_owner ∈ {platform, provider}`；**客户端自身错误只计入分母、不计入分子**。投标人须说明其 SLA 的分子分母定义，拒绝「成功率」笼统表述 | ★★★ |
| 归因可验证 | 服务方须能对任意一笔失败请求出示上游判决证据（状态码 / 上游错误事件）；无上游判决的内部错误须计为服务方故障，不得推给客户 | ★★★ |
| 可用性 | 核心对话端点 **≥99%** | ★ |
| 故障切换 | 单账号故障须在同一请求内自动切换到下一可用账号，客户端不感知；对「换号无效」类故障须立即透传而非穿池重试 | ★★★ |
| 流式完整性 | 已开始输出的流中断须明确标记，**带内 SSE 错误计为失败**，不得以 HTTP 200 冒充成功 | ★★★ |
| 数据可靠性 | **RPO ≤15 分钟；RTO ≤30 分钟；PITR 窗口 ≥7 天** | ★★ |
| 变更窗口 | 计划内变更提前 ≥24 小时通知；蓝绿发布，单次切流不可用时间 ≤5 秒；支持一键回滚 | ★★ |

### RPO / RTO 口径说明

- **RPO（恢复点目标）= 最多丢多少数据**。RPO ≤15 分钟表示故障时最坏情况下丢失故障前 15 分钟内的写入，更早数据必定可恢复。由备份频率与 WAL 归档间隔决定。
- **RTO（恢复时间目标）= 最多停多久**。RTO ≤30 分钟表示从开始恢复到数据库可用并通过关键校验不超过 30 分钟。由备份拉取速度、数据量与恢复流程决定。
- 两者独立：备份再勤（RPO 好）也不代表恢复快（RTO 好）。
