## 一、大白话口径说明

这份表回答两件事：

1. **钱花在哪**：每个账号在本周期一共结算了多少；以及按 5 小时 / 7 天切出来的**非重叠周期**里，烧得最猛的那一档分别是多少。
2. **峰值有多高**：周期内按「每分钟」统计的请求峰值（RPM）和 token 峰值（TPM，单位 million）。

### 月度总量（month）

- 周期内该账号所有 `usage_logs` 行的 `total_cost` / `actual_cost` 合计（不做额外 status 过滤）。
- 当统计窗是一个自然月时，**month 最大值 = 月度总量**。

### 5h / 7d 最大值（非滚动、步进切片）

- **不是**滚动窗口（不是每小时/每天挪一下）。
- 从周期起点起，按固定步长切成**互不重叠**的完整格子：
  - **5h**：步进 5 小时，只保留完整 5h 格；
  - **7d**：步进 7 天，月末不足 7 天的尾巴不进候选。
- 对每个账号，在这些格子里取 **total_cost 最大** 的一格，并给出该格起止时间。
- 这样更贴近上游「5 小时额度 / 周额度」一类周期（对齐到本报告周期起点；上游真实 reset 时刻可能仍有偏移）。

### 峰值 RPM / TPM

- 只看周期内 `usage_logs`。
- 按分钟桶：该分钟请求数 = RPM；input+output+cache token 合计 = TPM。
- **TPM 以 million 计**：原始 token 数 / 1,000,000，保留两位小数。
- 取周期内最大分钟值，并标注出现时间（北京时间）。

### 其他注意

- Edge 与 Prod 是各自本地账本，同名账号不能直接加总（ID 也不共用）。
- 某环境无匹配账号时明细为空，汇总计 0。
- 只纳入 **创建时间早于 period_end** 的账号；周期结束后新建的账号不进表。
