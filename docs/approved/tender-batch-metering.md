# 包 2 批量推理、限流和计量验收

依据《包2 社会心智基础大模型第三方API调用服务 技术需求书》。条款号按附件正文；2.2 表的第 4、5 项是不同指标。

| 项目 | 标书要求 | 拟交付与验收 |
| --- | --- | --- |
| Batch 可用性与吞吐 | §2.2 第 5 项允许声明不支持。若响应支持，聚合至少 5,000 Token/s，或具备等效能力（例：一批 1 万条在 24 小时内完成）。支持提交、查进度、批量拉取结果和失败重试。第 4 项另要求采购人至少 100 路并发，临时提额申请一个工作日内响应。 | 在每个目标站点使用独立私有对象存储。部署时从凭据管理系统注入 managed_batch.storage，验证上传、跨应用节点读取和删除。保留逐样本限额和鉴权。按真实模型、输入输出长度和并发记录整批起止时间及有效 Token。 |
| 重试、熔断和优先级 | §2.2 第 6 项要求月度 API 成功率（排除 4xx 客户端错误）和批量任务级成功率各至少 90%，失败样本自动重试且不重复计量。标书没有给出熔断阈值或优先级等级。 | 批量优先使用交互请求以外的剩余容量；上游限流或不可用时按已有账号冷却和 Retry-After 延迟派发，恢复后有限放行。仅重试已知可重试结果；不确定结果先对账。以批次和样本的稳定标识防止重复扣费。 |
| 到期删除 | §2.1 总体要求第 1 项禁止采集、存储、转卖采购方请求数据。第三章第 1 项约束请求数据的采集和存储，须取得采购人事先书面同意。§5.2 第 2 项要求按采购人要求，在合同终止或到期后 30 日内完成数据导出移交，并按要求删除留存数据及出具书面确认。标书未规定每个 Batch 文件的 TTL。 | 按文件已公布的 expires_at 即时拒绝读取或引用，后台幂等删除对象及数据库内的请求和结果副本。区分内容和计量记录；多副本、存储故障、在途任务和退出移交分别验收。 |
| 批量价格 | §2.5 第 6 项要求全部支持模型与官网价格逐项比较，覆盖读写、缓存命中、批处理。没有统一折扣。 | 在目录中分别列出官网价和对客 Batch 价、币种、计价单位、适用模型和生效时间。按成交价格快照结算；官网没有 Batch 价时明确说明。以同模型同步和批量各一笔核对展示、扣款和账单。 |
| 429 | §2.2 第 8 项要求触发限流时返回标准错误码和 Retry-After。 | 在 HTTP 响应提交前写入，保留已有上游值，已知重置时间取其剩余秒数。对 Key 时间窗口、队列、并发、账号和上游耗尽分支逐路用真实 HTTP 断言。已发送流的终止事件需单独验证。 |
| 鉴权错误 | §2.4 第 1、3、4 项分别要求 OpenAI API 兼容，支持凭证发放、轮换与吊销，对接采购方网关鉴权、限流、审计。正文没有逐字段规定错误体。 | 现有中间件会拒绝缺失、无效或已停用的凭证。验收时用采购方 SDK 检查能否处理现有错误；仅在出现实际兼容问题时记录对应路由与响应。 |
| 月度对账单 | §2.5 第 2 至 4 项要求按月提供调用次数、输入 Token、输出 Token（含适用的思维链 Token）、缓存命中 Token、成功率。相同筛选条件下与查询接口、控制台一致；支持账号、应用、模型、时间维度及导出。 | 同一租户和账期用共享统计查询生成可下载账单；按合同账期时区取左闭右开区间。保留失败请求作为成功率分母的来源，排除 4xx 客户端错误。验证跨月、零调用、含推理 Token、重试、失败无扣款及租户隔离。 |
| 保留期 | §2.1 总体要求第 4 项规定服务期限至少一年，可续期。§2.5 第 5 项要求计量数据至少留至服务期满后 6 个日历月。第三章第 3 项另要求请求行为日志至少 6 个月。 | 计量数据至少保留至实际合同期满后 6 个月；续期同步顺延。账单和计算其成功率所需的事实同期限保留。用闰年、长短月、续期与现有 400 天配置验证。已删除的数据只能按历史可恢复范围核实。 |

## 实现边界与待定业务口径

腾讯美西和北京站点分别在各自的 compose.override.yml 中配置私有 COS 桶和区域端点。部署时在各站应用节点的保密环境文件注入 MANAGED_BATCH_STORAGE_ACCESS_KEY_ID 和 MANAGED_BATCH_STORAGE_SECRET_ACCESS_KEY。每站运行身份仅需本桶 managed-batch/* 的 GetObject、PutObject 和 DeleteObject 权限。缺少凭据时 Batch 返回 503。现有处理器逐条执行已认领样本，上传路径为输入文件设置 24 小时到期时间。负责人审批前以本 PR 中的处理器原型验证单批有限并行。单元测试同时阻塞两个独立样本，确认二者都已进入执行器，再释放并验证终态。

正式实现沿用 batch_files、batches、batch_items 和现有 outbox。文件上传后创建批次，逐条认领执行，持久化结果，幂等结算，再生成下载文件。批次完成窗口、文件读取期限及合同计量留存分别处理。队列租约丢失时须终止继续派发，以每次认领的唯一令牌隔离迟到写入。

请业务负责人确认对客 Batch 售价来源（建议沿用已批准的逐模型合同报价；无价模型暂不开通），以及采购方计量保留截止日来源（建议使用合同实际到期日，续约时更新）。这两项会直接改变扣款金额与删除日期。对账单建议采用合同约定时区，国内合同默认北京时间。生产凭据和值班账号不进入仓库。

## 验证入口

在 backend 目录运行 `go test -tags unit ./internal/batchworker`。正式验收还需在授权环境跑文件全流程、真实吞吐、重复投递、限流和 SDK 鉴权回归，以及通过 Playwright 下载月账单后与相同条件的 API 数据逐项核对。单元测试不能证明服务级吞吐。
