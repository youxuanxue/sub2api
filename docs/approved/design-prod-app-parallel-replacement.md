- `galaxywaveai.com` 的权威 DNS 为阿里云（`dns29/dns30.hichina.com`），只有一条 A 记录指向 cn-prod `154.8.214.179`。

**TTL（已于 2026-11-13 改为 60 秒）**：实测 Porkbun 账号最小 TTL 为 60 秒；
文档中"通常 600"的说明不适用于本账号。已改为 60 秒的记录：
`tokenkey.dev`、`api.tokenkey.dev`、`api-cn.tokenkey.dev`、`callmodel.io`、`api.callmodel.io`。
记录 ID 与改前 TTL 为 300，回滚可把 TTL 改回 300。`node1-check.tokenkey.dev` 未改。

**探测器**：
- 独立小机，阿里云北京轻量应用服务器 `swas.s.c2m05s20b1.linux` 为候选（35 元/月，未购买），或 1 GB 档 40 元/月。
  价格为 ListPlans 标价，首年与续费以控制台为准。
- 不部署在应用机、数据机或代理出口机上。
- 探测方式：对每台应用机 IP 使用 `--resolve` 访问 `https://<域名>/health`，不经 DNS。
- 摘除：同一台应用机连续 3 次失败（间隔 10 秒）后，从 Porkbun 摘除其 A 记录（按记录 ID 删除或改写）。
- 回加：连续 5 次成功后恢复记录。
- 保护：任一域名的最后一条可用记录永不摘除；两台都失败时只告警，不动作。
- 动作白名单：只允许对上表记录 ID 执行删除/新增；不允许其它 DNS 写入。
- 探测器自身：心跳由 Better Stack 监控。用户已在控制台确认 Better Stack Free 不支持 Webhook；Free 是否支持 heartbeat 尚未核实。

**凭据**：Porkbun 与阿里云密钥分开存放，权限 600，不进仓库，不打印。
Porkbun 凭据仅用于 DNS 记录的读写；阿里云凭据仅用于 SWAS 查询与探测机装机，不用于 DNS 写入。

**已知限制**：
- 客户端不遵守 TTL（如 Java 默认 DNS 缓存）或已建立的长连接不会因 DNS 变化断开。
  依赖调用方连接超时和读超时；这是剩余最大风险，需逐个调用方核查。
- 整机宕机与应用进程故障都由探测器摘除，但摘除后切换窗口约为：
  判定时间（约 30 秒）+ TTL（60 秒）+ 解析器缓存差异。新连接约 1.5 至 2 分钟内切换完成。
- 探测器失效时不会自动摘除，需依赖心跳告警发现。

**仍未完成的门禁**：探测器装机与验收、白名单记录 ID 冻结、摘除/回加的演练（先告警模式运行一周）、
调用方超时核查、回滚演练。

**待设计的问题（未解决，实现前必须补齐）**：
- 健康检查语义：`/health` 检查哪些依赖；五个域名的单域名故障是否会把整机从所有域名摘除。
  新机 2026-11-13 之前的重启记录显示 `tokenkey.service` 曾 failed，需确认现行 `/health` 不会误报。
- 探测粒度：逐域名还是逐 IP；`api-cn.tokenkey.dev` 与 `galaxywaveai.com` 的关系。
- 单点探测：探测器在北京，探测美西 IP。需要多点确认或跨探测源投票，避免单一路径误判。
- 摘除上限：同一时间最多摘除几台、两台失败时的动作。
- 记录 ID 变化：删除后重新新增会生成新 ID，白名单需要有更新机制，不能假设 ID 冻结。
- Porkbun 写操作非原子：删除成功而新增失败时，域名可能无可用记录。需要定义写后回读、失败重试和状态存储。
- 硬编码 IP 的调用方不会随 DNS 切换，需要逐个排查。
- 告警接收人与升级路径：探测器失效时的值班责任人未定义。

### 实现与验收顺序

1. 选定入口接入方式与预算，在改正式 DNS 前验证全部正式域名和兼容入口。
   旧 DNS 缓存、直连旧 IP 与旧连接仍可能存在，不停止任何仍有流量的节点。
2. 多节点发布复用现有单机蓝绿 owner，在外层增加跨节点互斥与逐节点编排：
   检查另一节点可独立承载，再摘流、排空、更新、验证、重新加入。
   同一时间只处理一台；失败保留另一台服务，不自动扩大操作范围。
3. 双节点验收共享登录/OAuth session、账号凭据刷新锁、认证缓存失效、并发/RPM 限制、
   调度租约、后台单例任务以及媒体任务/文件可见性。已有 Redis/数据库协调代码不是线上验收。
4. 排空同时检查入口不再分配新请求、全部本机活动颜色的 HTTP inflight 为零，
   并等待异步 usage/计费工作完成与落库。进程内队列不能因 inflight 为零就视为已持久化；
   突发进程丢失下的计量恢复能力另行验证，不将应用 HA 等同于计量零丢失。
5. 新机小比例接流后，摘旧机但不停止旧机。用长流、keepalive 和计量证据验证没有主动截断，
   再验证新机独立承载完整业务峰值及资源余量；随后重新加入旧机并反向演练。
6. 硬故障先用隔离测试流量或已排空节点演练，记录探测窗口、恢复时间、在途断流和租约回收。
   已排空节点故障不证明带载崩溃无影响；对真实用户带载注入仍需独立授权。

### QA 集中管理方案（用户已同意，尚未执行）

用户在本会话明确回复“同意 QA 方案”，批准本节架构与实现方向；线上安装、owner 交接与删除操作
仍须通过实现、测试、review 和执行门禁，不把架构同意记为线上迁移已完成。

数据库备份和 WAL 已在数据机运行，不重复搬迁。将 QA 分区预建、共享数据库分区清理
与归档调度集中为数据机上的唯一协调 owner；各应用只做异步 capture 和本地短期缓冲。
大文件从各应用机直接归档到 node1，不在数据机增加 raw 中转副本，不把应用 QA 目录挂载成
数据机 NFS，也不引入同步远端写文件路径。QA 传输/校验限速、限内存并避让数据库备份。

集中执行本身不会修复现有 `site/hour` 目标覆盖：源数据仍分布在两应用机。
归档与 receipt 必须绑定站点、稳定的 capture source 身份、UTC 小时及内容摘要；
同小时各源隔离发布，重试不得覆盖已校验的其它源。稳定 source 身份不复用蓝/绿颜色或镜像版本。
旧布局只读兼容，不把旧单源 receipt 冒认为所有节点均已归档。

清理分为两个作用域：共享数据库分区只在数据机处理；每台应用机独立清理自己的热文件。
归档仍须核对历史参与源、封口与 receipt，不把一台节点 archive 成功当作全站完成。
节点故障、回执缺失或迟到文件须保留明确未完成状态；源完成须确认 capture 队列封口，不能只看墙钟跨小时。
每节点清理完成单独记录，不能复用一个全站 `hot_files_cleaned_at` 声称所有磁盘均已回收。

2026-11-12 用户明确批准并确认：业务磁盘优先，QA 小时结束满 24 小时后接受丢失并强制清理，
单条数据最多约 25 小时，另加调度、锁竞争及执行时间。应用机本地 payload/DLQ 和数据机 QA
小时分区各用独立定时任务，不依赖协调器、对端、归档成功或 capture seal。数据机仍保留数据库
主库/分区校验、advisory lock、短锁超时和事务复核；不执行任意表删除。应用机只删除精确的 QA
小时目录，拒绝 symlink 越界。node1 已归档数据保留期、业务数据、计费和备份不变。
未证实归档的过期删除明确记为接受丢失，不伪造 archive 成功；磁盘已满导致审计文件写失败时，
仍尝试释放应用机 QA payload，并报告审计错误。删除不可逆，停 timer 不会恢复。
归档协调器只处理保留期内的小时，过期数据交给独立兜底，不重新归档空目录冒充完整。
兜底故障须告警，不能声称此策略能绝对防止磁盘满；最近一天增量过大仍需要容量监控。
本节尚未安装新 timer、复制 raw、停用旧 owner 或删除分区/文件。

### 数据机协调器实现（线上未启用）

实现入口为 `ops/qa/coordinator_host.py`、`source_worker.py`、`data_machine_coordinator.py`
与 `source_cleanup.py`，配置与交接见 [运行手册](../../ops/qa/COORDINATOR.md)：

- 数据机根据历史 source 参与区间调度应用机，应用机封口后直接向 node1 传 raw；
- 数据机协调器读取 source-isolated node1 receipt 与 capture seal，按 source 生成不可覆盖的小时计划；
- 归档协调器只处理未过期的完整 UTC 小时，记住已归档小时，不重复处理，不调度删除；
- `force_retention.py` 在两类主机独立执行：应用机删除过期 QA payload/DLQ，数据机调用
  `expire-shared` 删除过期 QA 小时分区；均无需 source receipt，也不等归档 owner 锁；
- source 清理器只删除本机精确小时目录，不能删除另一节点文件，也不能越权删除共享分区；
- 强制清理支持部分删除重试和迟到旧文件再次回收，不用全站磁盘完成标记。原有按回执授权
  的策略/清理工具保留兼容，但不再作为协调器的周期任务；
- 安装默认仅计划，显式 apply 也不启用 timer；调度有限流、备份避让与独立积压告警接口。

本实现不执行线上交接；真实主机身份、source 历史起止、旧小时迁移、SSH/PG 权限、停用旧
timer、启用新 watcher 与现场验收仍需单独执行。在验收完成前，不启用新的 source owner。
